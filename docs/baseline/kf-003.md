code. `todo.md` was expanded and marked IN_PROGRESS before implementation.

  opening-thread owner, storage-assigned contiguous offsets, segment rotation,
  completed-write receipts, captured-boundary immediate reads and explicit failure/close.
- `LogFormat`: exact big-endian V1 segment/record/index encodings, CRC32C over metadata
  and original bytes, strict lossless UTF-8 identity and bounded prefix validation.

  package-private controlled I/O seam. No shared channel cursor or executor pipeline.

  accidentally releasing POSIX process locks. It contains no broker/log state.

  invalid-input, capacity, corruption, ownership, failed, closed and budget errors.

## Observable acceptance evidence

Literal expected frame bytes were independently calculated with Python `struct` and
bitwise Castagnoli CRC, checked against CRC32C(`123456789`) = `e3069283`. Tests also
construct independent fixtures without production codec helpers. They verify exact
binary/empty payloads, absent/present-empty keys, timestamps, qualified identities
and immutable returned values.

Malformed header/frame versions, flags, lengths, offsets, checksums, UTF-8 identities,
wrong partitions/topics, segment gaps and unsafe entries fail closed without log
modification. Length/position/configuration overflow checks precede variable allocations
and out-of-file reads. Offset exhaustion is tested at the exact increment guard;
tests do not fabricate billions of stored records to reach Long.MAX_VALUE.

Short two-byte reads/three-byte writes and intermittent zero transfers complete at
the correct positions. Persistent zero progress fails after the configured eight
attempts. Injected partial frame/index/rotation writes leave the completed boundary
unchanged, preserve the original exception and fail further I/O. A complete frame
whose index write failed can reappear on valid reopen; this explicitly demonstrates
an uncertain write outcome, not a successful acknowledgement or durable publication.

Exact segment-size fits, oversized frames, max-segment exhaustion and CREATE_NEW
collisions preserve offsets/files. Reads cross segments with bounded records/bytes,
continuations, explicit budget errors, zero-byte record counting and captured end
boundaries. Sparse lookup's skipped frames/bytes and live channel count are checked.

Missing/stale/truncated/wrong-version/invalid indexes are rebuilt, including entries
with valid CRCs but unsafe offset/position/length fields. All segments must validate
before any index repair; a corrupt later segment cannot trigger misleading earlier
repair. Clean reopen preserves every log/index byte, and a complete empty final
segment is reusable. Rebuild failure releases resources and leaves log bytes intact.

Separate directories accept identical identities. Same-process symlink/`..` aliases
and actual separate-JVM contenders cannot acquire a held directory. Tests also prove
that rejecting a same-process contender does not release the OS lock. A barrier holds
the owner mid-write while wrong-thread close and other owners fail; release allows
completion and clean ownership transfer. Concurrent reads are explicitly rejected,
so no read/write concurrency guarantee is claimed. Subprocesses have 10-second bounds
and five-second forced-cleanup waits; these are ownership tests, not power-loss tests.

Initialization failure and ordinary close release resources even when cleanup fails;
primary exceptions retain suppressed cleanup errors. Repeated owner close is harmless;
append/read/boundary capture reject afterwards, while state inspection remains available.

Both real standalone and Spring V1 Append calls still returned `UNIMPLEMENTED`.
