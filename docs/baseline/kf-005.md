## Limitations and KF-006 handoff

Durability relies on persistent local filesystem/device semantics honoring file force,
atomic replacement and directory sync. Linux is the reference environment; local APFS
and process-halt tests are not physical power-loss proof. Catalog V2 cannot be opened
by old KF-004 binaries. Missing/corrupt authority fails closed, never resets groups.

Join membership is not idempotent: cancellation/lost responses can leave sessions until
expiry and retries can consume more capacity. Labels grant no authority. Tokens are
credentials, not transport authentication; fencing cannot stop processing already-read
bytes. Heartbeat success in degraded mode does not restore writable readiness. An
unresolved writer keeps its ownership until actual completion, including during shutdown.

KF-006 is unstarted. Add immediate bounded Fetch and durable next-offset Commit with
current apply-time validation. A previously returned ownership-check result is not
continuing authority. Before applying a commit, install the commit/rebalance barrier so
affected ownership cannot move until the write outcome is resolved. No offsets, replay,
reset, long polling or retention were introduced here.
