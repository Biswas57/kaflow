## Implemented boundaries

- Prototype cluster, helper and factory registry ownership is injected. Spring owns
  its context/service cleanup; standalone and CLI composition roots own cleanup;
  standalone test servers install no global shutdown hooks. REST and legacy gRPC
  share the same controller. No global cluster lookup/reset or static factory cache.
- `kaflow.broker` is a separate bounded volatile core: immutable bytes, qualified
  identities, fixed partitions, deterministic routing, exact receipts, admission,
  retained accounting, ordered close and bounded package-private inspection.
- `kaflow/v1/broker.proto` generates unary single-record Append messages/stubs only.
  Neither running entry point registers a V1 implementation. There is no adapter
  from volatile insertion to successful network acknowledgement.
- No persistence, Fetch/Commit implementation, group leases, subscriptions, retention,
  migration, dependency/wrapper upgrade or prototype payload/routing/offset repair.

## What the tests establish

Binary/empty values and invalid UTF-8 survive storage and schema round trips; mutated
input/output arrays cannot mutate immutable commands, records or snapshots. Absent and
present-empty keys differ. Qualified identities separate topics and independent cores.
Literal routing vectors come from independent SHA-256 calculations, not the routing helper.

Synchronous calls preserve same-partition order. Eight concurrent callers insert 800
unique payloads across six qualified partitions with exact receipt-to-record matching,
unique contiguous offsets, no unmatched receipts/records, and zero remaining admission.
They make no thread-start, timestamp or overlapping-producer ordering assumptions.

Independent tests cover every configured count/byte limit, zero-byte count exhaustion,
shared immutable-reference charging, invalid/missing targets, no eviction, checked
offset overflow, rejection stability, and exceptions before the lock and before commit.
Offset overflow is tested at the exact increment guard, without fabricating log state
or allocating billions of in-memory records.

Barrier tests force admitted work to wait behind the mutation lock and force both
close orderings. An intervening accepted append checks that a paused admitted call
has not consumed routing/offset state. Close clears topic/log references and retained
accounting while leaving outstanding reservations for their owners to release; former
immutable snapshots remain valid. Both new topic creation and append reject after close.
Inspection respects 128-record/2-MiB caps, lower requested counts and immutable paging.

Actual V1 unary calls to both standalone and Spring servers returned `UNIMPLEMENTED`.
The Spring integration test created a topic through HTTP, produced via legacy gRPC and
observed it through the shared controller, proving runtime composition rather than only
bean configuration. Generated core/model/stub classes were also inspected in the JAR.

Packaged smoke used HTTP `127.0.0.1:57156` and gRPC `127.0.0.1:57157`: health 200/UP,
topic creation 201 and read 200. SIGTERM exited 143 after 0.476 seconds; both listeners
